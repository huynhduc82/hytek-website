SECS/GEM · HSMS

How semiconductor equipment talks to the factory host: three standards stacked on top of each other, each with one job.

What it is

  1. GEM SEMI E30

    What the equipment must do: communication and control states, collection events, alarms, status variables, remote commands and recipe handling. The behaviour a host can count on from every tool.

  2. SECS-II SEMI E5

    The language: messages named by stream and function (S1F13, S6F11…), with a body built from typed items such as lists, ASCII text and unsigned integers.

  3. HSMS SEMI E37

    The transport: carries SECS-II messages over TCP/IP, with a 10-byte header and a small set of control messages to open, check and close the session. (The older SECS-I, SEMI E4, does the same over RS-232.)

Where it sits in the equipment

GEM sits on top of the equipment control software. The tool keeps running its own sequences, devices and interlocks; the GEM layer reports what happens to the factory host and accepts the host's commands when the tool allows it.

HSMS connection states

  1. NOT CONNECTED
  2. CONNECTED · NOT SELECTED
  3. CONNECTED · SELECTED

    The equipment waits as the passive side. After TCP connects, the host must select the session before T7 runs out; only a selected session carries data messages.

    The header says who the message is for, which stream and function it is, whether a reply is wanted (W-bit) and which request a reply answers (system bytes). The body is a tree of items; a list counts its items, every other format counts its bytes.

    Key terms

    Stream / Function
    The message name. Odd functions are primary messages, the even function after it is the reply (S1F13 → S1F14).
    W-bit
    Set on a primary message when the sender wants a reply.
    System bytes
    A number chosen by the sender and copied into the reply, so replies can be matched to requests.
    Select / Linktest
    HSMS control messages: open the session for data, and check that the other side is still alive.
    T3 · T7
    Timers: T3 is how long to wait for a reply; T7 is how long a new connection may stay unselected.
    Collection event
    Something that happened on the tool (a state change, a process step) that the host can ask to be told about, with chosen data attached as a report.
    Alarm
    A condition reported when it is set and again when it clears.
    Remote command
    A command from the host such as start or stop, accepted or rejected by the tool.

    Common pitfalls

    • Replies that arrive after T3: the sender has already given up, so the late reply is an error, not an answer.
    • A session that is connected but never selected: no data flows, and T7 closes it.
    • System bytes not copied into the reply, or a reply sent when the W-bit was not set.
    • Event reports sent before the host has defined and enabled them.
    • Mixing up the communication state (is the link up?) with the control state (online or offline, local or remote).
